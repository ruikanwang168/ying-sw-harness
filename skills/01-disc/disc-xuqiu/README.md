# disc-xuqiu

`disc-xuqiu` 用来把模糊需求整理成可落地的需求文档结果，支持两种模式：

- 从零模式：新系统 / 新产品 / 新模块
- 增量模式：现有项目新增需求 / 二开 / 改造已有模块

输出两类文档：

- `PRD.md`
- `AI开发说明书.md`

边界：

- 这个 skills 只做需求澄清、现状分析和文档产出
- 不修改任何代码、配置、脚本、数据库或项目文件
- 当用户明确要求开始生成文档时，默认直接创建或更新目标 `.md` 文件
- 聊天窗口只输出简短简介，不直接贴出整份正式文档

## 使用节奏

推荐按这个顺序使用：

1. 先确认这是新需求，还是增量需求
2. 进入对应模式持续聊需求
3. 等需求聊到差不多时，再决定生成什么文档

也就是说，第一次进入 `disc-xuqiu` 时，不需要先决定是要 `PRD.md` 还是 `AI开发说明书.md`。
通常是先把需求聊透，等你说“差不多了”“开始出文档”之后，再继续选择文档类型。

固定分支问题直接让用户选，不走自由输入。

例如：

- 第一次只给两个选项：`新需求` / `增量需求`
- 需求收敛后只给三个选项：`PRD.md` / `AI开发说明书.md` / `两份都要`

## 常见用法

### 1. 只梳理需求

```text
帮我先梳理一下这个系统需求
```

### 2. 生成人类版 PRD

```text
帮我把这个需求整理成 PRD
```

### 3. 生成 AI 开发说明书

```text
这份文档还要给 AI 开发，请再整理成 AI 可执行的实现说明
```

### 4. 同时输出两份文档

```text
帮我梳理需求，先出 PRD，再补一份给 AI 开发的说明书
```

### 5. 增量模式用法

```text
这是在现有项目里新增一个审批模块，你先学习下当前项目和历史 PRD，再帮我出 PRD 和 AI 开发说明书
```

增量模式下，推荐节奏是：

1. 先确认是 `增量需求`
2. 先检索目标模块相关代码、README、历史文档
3. 先整理一版当前现状和影响范围
4. 只对代码里看不出来的模糊点继续追问
5. 等你说“差不多了”之后，再选输出 `PRD.md`、`AI开发说明书.md` 或两份都要
6. 明确开始生成后，直接写入对应文件，聊天里只回文件结果和摘要

## 对话示例

推荐的真实对话节奏：

1. 第一轮只让用户选：
   - `新需求`
   - `增量需求`
2. 然后持续聊需求，不急着问文档类型。
3. 等用户说“差不多了”“可以开始写了”。
4. 最后再让用户选：
   - `PRD.md`
   - `AI开发说明书.md`
   - `两份都要`
