# 运行与截图规范

范围内有可见界面时，从功能覆盖清单派生配图清单。逐项记录功能、页面或入口、终端/角色/状态、图的来源和正文位置。默认覆盖每个范围内主要业务页面，以及独立的关键表单、弹窗、抽屉、流程步骤和会影响验收的可见状态。新增与编辑共用同一界面且关键差异可清楚说明时，可合用一张图并标明差异。后台任务等没有界面的条目用文字或必要的流程图表达。用户明确要求纯文字时按指定格式交付。

## 获取和标注

- 优先使用用户提供并可核对的原型图或现有截图。缺图时在可访问且获准使用的原型或测试环境打开对应功能，使用演示数据采集。页面验证使用实际 HTTP(S) 页面、对应角色和真实或仿真的目标终端。静态设计稿、既有图和现场截图分别标注来源。截图展示原型现状时，在相邻正文指出与目标行为的实质差异。
- 需要启动时先核对项目路径、版本状态、锁文件、启动说明、已有服务和端口。按锁文件选择包管理器，避免升级或改写工程依赖。只记录本次启动的进程、端口和必要日志。不得读取、输出或写入真实凭据。创建、编辑、删除、审批、发布、支付或发送消息等验证仅在相应授权范围执行。
- 把图嵌入对应功能的小节，说明入口、关键状态或当前角色。长表单或多步流程按对读者有用的画面拆图。共享图片可引用正文中的具体位置，并列明它覆盖的场景。每张图逐张检查关键内容是否完整可读、是否对应业务与状态、是否包含需要处理的敏感信息。

## 交付检查

先从正文逐项核对配图是否覆盖，再核对图片能否渲染。缺少材料、权限、环境或原型状态时，在对应小节写明缺哪个画面、原因和已使用的核对方式。截图与业务规则分别对账，图片证据仅证明其展示的现场状态。使用相对路径保存图片并与 Markdown 一并交付。若产出压缩包，解包核对 Markdown 引用的图片均随包且可打开。交付时标出实际验证范围和仍有缺图的界面。作为交付入口的本地服务保持可用，辅助进程只处理本次启动的部分。
