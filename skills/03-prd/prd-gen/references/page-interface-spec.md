# 页面、控件与接口覆盖标准

按交付范围对账。全量需求逐项覆盖所交付的页面、控件、系统能力和接口。增量需求追踪所有受影响的页面、控件、数据状态、接口和调用方，包括可确认的间接影响。共享规格可引用并标明适用条件。

## 页面和操作映射

盘点页面、弹窗和抽屉对应的角色、数据范围、来源及实际状态。逐项核对各类控件、筛选、表格列、汇总和行操作，结合页面行为与系统结果描述业务差异。面向研发规格时，让受影响的页面操作可追到对应接口、页面反馈和数据或状态结果，标明纯前端行为。每个接口应能追到页面动作、系统任务、回调或外部调用方。页面细项见[页面说明要求](page-description-rules.md)。

## 接口与系统行为

正文优先描述影响使用与验收的契约，包括谁或什么事件触发、传入哪些业务信息、必须校验什么、结果如何返回、影响哪些页面或数据，以及异常如何处理。交付需直接用于开发的详细规格、用户要求接口级说明，或外部对接和跨系统同步依赖细节时，逐个受影响接口说明适用项：

- 已有、新增或变更，调用方、触发时机、方法和路径、请求响应字段、校验与权限。
- 业务处理顺序、数据读写、状态转换和记录、通知、审批、文件或下游任务等关联结果。
- 重复请求、并发、超时、重试、整体或部分成功、业务异常和恢复，以及与页面反馈的关系。

从代码追踪前端调用、路由或控制器、服务和模型，分别记录当前实现与目标规则。拟新增接口以已确认的业务能力与约束为据。影响验收或外部对接的契约缺失时，注明具体问题和影响。待技术设计确定的方法、路径、表名和框架实现保持在对应设计阶段。

接口明细放在功能条目下或通过附录引用。正文中同一业务规则写在统一位置，使映射可查并避免多处口径分叉。
