# 业务操作研发契约

有独立触发条件、资格校验、处理或结果的业务操作，应能让前端、后端和测试得到一致理解。保存、提交、审批、撤回、删除、导入、导出、批量处理、状态切换、自动任务和回调按实际范围逐项核对。相关规则可以在同一功能条目中表达。

- **触发与前置条件**包括执行角色、页面入口或系统事件、可操作状态、数据范围和入口启用规则。
- **页面反馈**包括初始状态、相关字段、必填与联动、即时校验、确认、处理中状态、成功后的刷新或跳转、失败后的保留与恢复。
- **系统处理**包括需要执行的资格、权限、状态、唯一性或时效校验，必要的处理顺序，数据读取、计算、保留或变更，以及返回结果、操作记录、通知、审批实例和下游任务等关联结果。
- **异常和恢复**按场景说明无权、对象不存在、状态已变化、重复、并发、依赖失败、超时、部分成功和重试。影响产品结果的事务行为可以直接写成结果约束，例如「导入校验失败时，本批数据全部保留原值」。
- **验收**使用可观察的条件、动作和预期结果表达。至少覆盖主成功路径及影响业务结果的失败路径，核对页面与数据或状态是否一致。共用次要交互可以引用规则。

依赖外部系统、影响数据一致性或需要明确调用契约时，按对应功能补足研发所需细节。详见[页面、控件与接口覆盖标准](page-interface-spec.md)。
