# PRD 结构选择

先按读者的决策需要组织结构，不按固定目录套写。通常应让读者能找到：交付阶段、范围与目标、已确认能力、逐操作前后端闭环、验证依据、冲突裁决与待确认事项。

可按系统特点增加章节：

- 后台/运营系统：角色与数据范围、批量操作、筛选规则。
- 审批系统：流程节点、分支条件、状态矩阵、撤回与异常。
- 数据产品：指标定义、口径、粒度、时间范围、数据延迟、钻取。
- AI 产品：输入输出、失败反馈、人工兜底、评估标准与风险。
- 平台/API 产品：接入步骤、契约、配额、回调、兼容性与安全边界。

页面型系统必须让每个页面、控件、接口及其关系都有可定位的规格说明，但可按页面、任务、流程、模块或领域对象组织；非页面能力则围绕调用方、任务/事件、接口或服务能力、数据状态和验收契约表达。流程图、状态图和截图按理解与验证需要使用。

避免以章节数量、标题层级或表格列数衡量质量。相同事实只写一次；将证据定位保留在内部分析，不让正文变成代码审计报告。

若同一操作的页面、后端、数据状态和验收规则被分散到不同位置，应通过名称、链接、编号或上下文建立清晰关联，具体方式由文档结构决定。
