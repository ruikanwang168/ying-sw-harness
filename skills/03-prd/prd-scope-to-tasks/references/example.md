# 填写示例：退款进度与结果导出

仅用于理解拆分粒度。以下需求、权限和依赖都是示例给定条件，不得移植为其他项目事实。

## 示例材料

本次边界包含两个已有故事：`US-001 准确答复退款进度`、`US-002 交付退款核对结果`。原型和 PRD 明确：现有退款列表增加异常原因摘要；新增退款核对结果导出。现有代码已有退款列表与进度查询接口，尚无导出能力；本次不改退款审批。实际菜单为“售后服务 → 退款管理”，无三级菜单。

## 任务拆分清单

### US-001：准确答复退款进度

沿用材料：作为客服，我希望掌握退款阶段及异常原因，以便向客户给出准确答复。

| --- | --- | --- | --- | --- | --- | --- |
| US-001 准确答复退款进度 | T-001 退款列表调整（共用） | 关联功能：F-001、F-002；本次工作内容：现有列表展示退款阶段且无导出入口，本次增加异常原因摘要和导出操作，同时覆盖 US-002；验收要点：异常原因正确，原有查询可用，导出使用当前范围且成功失败均有反馈；依赖项：T-002、T-004。 | 修改 | 前端 | | |
| US-001 准确答复退款进度 | T-002 退款进度查询接口调整 | 关联功能：F-001；本次工作内容：现有查询返回进度，本次补充异常原因信息；验收要点：原因与退款记录一致，无异常时结果明确，原有查询范围和权限保持有效；依赖项：无。 | 修改 | 后端 | | |

### US-002：交付退款核对结果

沿用材料：作为客服主管，我希望将指定范围的退款情况交付核对，以便相关人员据此核查退款处理结果。

| 用户故事 | 任务描述 | 任务详细说明 | 变更类型 | 人员角色 | 人员 | 预计工时 |
| --- | --- | --- | --- | --- | --- | --- |
| US-002 交付退款核对结果 | T-004 退款核对结果导出接口 | 关联功能：F-002；本次工作内容：新增按已选范围生成核对结果的能力；验收要点：内容与查询范围一致，权限有效，生成失败不交付错误文件；依赖项：T-002。 | 新增 | 后端 | | |
| US-002 交付退款核对结果 | T-005 退款核对结果导出验证 | 关联功能：F-002；本次工作内容：验证核对结果交付及其与进度信息的一致性；验收要点：覆盖指定范围、空结果、权限不足和导出失败；依赖项：T-001、T-004。 | 新增 | 测试 | | |

退款列表的前端工作统一由 T-001 承接，US-002 依赖它，不再重复拆一条页面任务。任务变更类型依据交付对象判断，因此 T-001 是现有页面修改，F-002 仍为独立新增能力。
