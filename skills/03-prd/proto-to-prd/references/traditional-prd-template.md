# 常规 PRD 模板

用于没有指定公司模板的新需求或独立版本文档。以下是推荐顺序，不是必填章节列表；按实际内容合并或删除。已有 PRD 的增量更新沿用原结构，不为套本模板整体重排。

写作遵循 [基础规则](base-metadata.md)，功能粒度遵循 [功能说明规则](ui-patterns.md)。

## 更新记录、相关材料

记录本次真实变更；列出需求、原型、UI、旧版文档等实际材料。版本发布信息只有已给出时才写。

## 1. 需求说明与范围

简述问题、使用角色、本期目标。迭代说明新增或改变了什么、适用于哪些对象/终端、哪些继续沿用原流程。已有明确不纳入范围的事项简要列明。

## 2. 功能清单

按业务层级列出本期功能；只增加有对照价值的列。

| 模块 | 功能 | 需求说明 |
| --- | --- | --- |
| 版本管理 | 启动开发 | 组长确认满足估算条件后启动，锁定执行人与估算 |

本行为虚构写作示例，不是任何目标项目的既定规则。正式输出使用本期真实功能，可按需加“变更类型／适用角色／说明位置”。不另附同义的全量页面覆盖矩阵。

## 3. 业务流程与公共规则（有需要时）

- 涉及跨角色办理、多阶段、回退或修改分支时，给必要的流程或状态映射；单一 CRUD 可以省略本节。
- 权限、计算、状态约束等跨功能重复使用时集中定义，页面引用并补例外。只有局部使用的规则留在对应功能。
- 流程图与状态表选择最容易核对的一种；两者补充不同信息时可以并用，不为凑数量重复表达。

## 4. 功能说明

按模块、页面或业务任务设小节。每个功能只选适用的内容：

- **原型/入口**：对应原型区域、进入方式、涉及角色。
- **展示与输入**：列表字段、表单字段、筛选项；有明确规则时写必填、选项、默认、排序、校验和联动。
- **操作与结果**：按钮条件、点击行为、弹窗/跳转、保存与返回、重要错误后的处理。
- **业务规则**：计算、状态、权限及外部依赖；公共规则通过引用关联。

新建/编辑共享表单只写一次字段表，单列差异。确认弹窗可直接跟在触发按钮下，写确认内容、确认和取消结果。没有筛选功能时省略筛选说明。

优先使用真实原型图片或链接；长说明可采用“界面／功能说明”的形式，图片过宽或表格不利阅读时改为上图下文。仅在缺少清晰布局依据且布局影响理解时补充线框图。

## 5. 关键验收要点（未在功能内集中说明时）

覆盖本次核心目标与重要业务异常。无需重复字段表和完整操作步骤；完整测试用例只在用户明确要求时另行编写。

## 6. 待确认事项（有实际问题时）

列出具体缺口、影响和需要的材料/决定。没有问题时删除此节，不填写空表或“无”。

明确需要的性能、迁移、兼容或外部系统影响可放在对应功能，跨模块且内容较多时另设小节。不默认追加技术可行性、迭代规划、全量字典与附录。
