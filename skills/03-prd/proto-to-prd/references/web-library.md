# PC/Web 功能说明要点

只读取当前页面类型的部分，配合 [功能说明规则](ui-patterns.md) 使用。本文件是检查提示，不是组件方案或功能需求库；不能因为出现某类页面就添加这里列举的全部操作。

## 列表管理

说明可见数据范围、默认进入状态、筛选匹配与联动、展示列与排序、实际存在的行操作和批量动作。表格字段以业务含义为主，不默认规定像素宽度、列拖拽、列显隐、自动刷新或导出。

如列表与详情联动，说明打开新页、抽屉还是原位切换，以及返回后的筛选、页码等上下文。以已确认交互为依据，不统一指定新页签或固定分页条数。

## 新建与编辑

共用表单按业务区块定义一次字段，另写新建默认、编辑回显/只读、条件可编辑项与保存结果。有独立流程或明显不同字段时再拆分。

不默认增加保存草稿、重置、保存并继续、历史版本或强制覆盖。并发处理写用户可见结果，具体锁方案留给研发。

## 详情与工作台

按信息区块说明基础信息、业务进度、关联内容及可操作项。列表已定义的字段不重复建字典，补只读展示差异即可。

工作台若有待办、统计或多角色视图，分别说明数据范围、排序和点击结果，不从通用布局推导待办和日志能力。

## 看板与日期密集视图

说明指标公式、时间范围、刷新时机、筛选作用及下钻条件。人员/日期矩阵等页面重点说明每格数值含义、重叠合计、缺失与零值的差别、长范围如何访问和编辑后的影响。

不要把“工时”“占用百分比”“任务数”自动换算；转换关系只有材料明确规定时才写。

## 向导、导入与结果

按步骤说明输入、校验、前后移动的数据保留和最终提交结果。确认弹窗附在相应步骤下，只有具备独立复杂规则时才另设小节。

异步操作说明进行中、完成、失败或结果未明时如何查看和继续；不默认采用任务中心、邮件通知或固定轮询周期。

## 容器与通用规范

原型已确定的弹窗、抽屉、菜单等沿用实际形式。无明确要求的颜色、快捷键、动画、Toast 秒数和面包屑样式沿用现有产品约定，不在每个功能重写。

键盘、可访问性、浏览器兼容等属于本期明确需求时说明验收结果，不机械追加通用规范清单。
