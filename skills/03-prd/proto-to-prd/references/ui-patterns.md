# 功能与交互说明规则

本文件用于防止漏掉业务行为，不要求在正文为每项检查建立标题。按实际界面选用；列表、表单、弹窗都不自动带出模板中没有依据的能力。

## 1. 组织粒度

- 按业务模块与任务组织，复杂独立页面另设小节。
- 同对象新建/编辑共用字段表，写明入口、新建默认、编辑回显与不可改项、权限及保存差异。差异过大时拆分；共用项仍引用，避免复制。
- 简单确认弹窗跟在触发动作下，说明触发条件、确认内容、确定/取消的结果。复杂计算、独立审批或多步骤输入可另设小节。
- 已有页面/弹窗 ID 可用于内部追踪；多个 ID 映射同一小节时，逐项核对其行为，不以标题数量判定覆盖。

## 2. 列表、筛选和详情

按本期范围说明：

- 数据范围与来源；展示字段的业务含义、单位、格式、默认排序，以及必要的空值含义。
- 筛选项类型、选项来源、匹配方式、默认条件、组合与联动、查询触发和重置结果。
- 行操作、批量操作的适用角色/状态、点击行为、确认要求和结果。存在批量操作时补全选范围、不可处理项和部分失败如何反馈。
- 有分页或加载更多时说明其业务行为；不默认添加自动刷新、跨页全选或多列排序。
- 详情按信息区块说明展示与关联操作，复用字段含义，只补展示和可编辑差异。

字段较少时用条目；需要逐项比较时可用“字段／展示规则”或“筛选项／类型与默认／匹配与联动”等表头。不强制写列宽、图标、英文变量。

## 3. 表单与保存

建议用一张表承载输入规则：

| 字段 | 类型/取值 | 必填 | 默认/回显 | 校验与联动 |
| --- | --- | --- | --- | --- |
| 预计工时 | 小时，正整数 | 是 | 编辑回显已有值 | 仅本人在未锁定时可修改 |

上行为虚构写作示例，不能直接作为目标业务规则。字段很多时按业务区域分组，删除无对照意义的列，不能因删列丢失真实约束。

保存说明包含有业务意义的结果：改变哪个对象/状态，成功后关闭或去哪里、哪些关联内容更新；校验失败是否保留输入。已定义的通用反馈只引用一次。取消、未保存离开、并发冲突等按项目约定或已确认设计处理，不把“强制覆盖”当作默认能力。

## 4. 反馈与容器

准确称呼弹窗（Modal）、侧边抽屉（Drawer）、底部面板（Bottom Sheet）与轻提示（Message/Toast）。只在容器形式影响操作或上下文时强调，不重复解释组件定义。

区分无数据、筛选无结果、加载失败、无权限。重要失败信息应让用户知道下一步；未拿到结果不能冒充业务失败或空结果。相同反馈在公共规则定义，特殊状态留在对应功能，不为每页复制同一异常清单。

## 5. 状态与计算

- 状态规则说明触发角色、条件、状态变化和后续可操作项；有回退、撤销、关闭、重启等实际能力时补其历史与关联影响，不自行新增这些动作。
- 对金额、比例、数量、日期等说明数据范围、公式/分母、去重、单位、精度、时间区间及空值；仅列该指标实际需要的信息。
- 权限说明数据范围、可见与可操作范围；不把隐藏按钮当作完整的权限需求，也不默认扩展租户、组织和角色体系。
- 与外部系统交互时说明业务触发、交换内容、返回结果和重要失败处理；不猜正式接口地址和内部协议。

## 6. 流程与原型

以下情况适合配流程图或状态表：跨角色交接、多阶段办理、回退/并行/修订分支，或文字难以看清的复杂条件。

- 选择能表达问题的流程图、状态表或状态图；同一关系不在多张图中重复绘制。
- 画出实际存在且改变结果的重要异常，不为每张图机械添加“失败重试”。有状态表时不必另画一张同义状态图。
- 图下补充条件、口径和例外即可，不逐节点翻译。不要附流程节点与页面 ID 对账表。
- 清晰原型图片/链接优先；缺少布局信息且影响理解时才补线框图。线框图标明是辅助示意，不当成从原型观察到的事实。

## 7. 特殊任务

- **向导**：说明步骤目的、必填、上一步/下一步、数据保留、提交结果；不要把每步复制成完整 CRUD 规格。
- **导入**：说明来源/模板、映射与校验、错误定位、重复记录处理、提交后的数据变化和历史保留。数据初始化会改变既有估算或阶段时，保留这些约束。
- **导出**：说明导出范围、字段、权限、结果获取；只在有依据时写数量限制、异步任务或通知。
- **看板**：以指标口径为重点，补筛选影响、联动、下钻和来源；不默认生成每张图的完整字段字典。
- **对话/生成**：仅对实际存在的发送、停止、重试、历史、引用等操作说明行为；结合 [AI 补充模板](ai-product-prd-template.md) 描述输出与人工控制。
