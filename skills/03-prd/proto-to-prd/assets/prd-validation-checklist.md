# PRD 内部自检清单

交付前读取并核对。以下是内部检查，不是 PRD 的必填目录，不默认将本表、覆盖记录或模板对账附在正文。只检查适用项，不为通过检查反向增加业务范围。

## 范围与事实

- [ ] 本期范围与用户确认或授权一致；迭代聚焦真实变化及受影响的存量行为。
- [ ] 原型、旧稿、用户需求有冲突时，已明确目标规则或列具体待确认项，没有静默覆盖。
- [ ] 未把演示人员、Mock 值、临时 API、推测的设计意图或未执行的核验当成事实。
- [ ] 日期、负责人、版本及状态符合目标项目要求，没有虚构审批、上线和效果数据。

## 业务覆盖

- [ ] 内部盘点的全部在范围功能、字段、操作和重要状态，在正文均有可定位的说明。
- [ ] 合并新建/编辑或弹窗后，仍明确各入口的默认、回显、只读、权限、校验、保存和取消差异。
- [ ] 筛选、列表字段、表单、操作、跳转/返回按实际需求写清；没有只列按钮名而无行为。
- [ ] 计算指标有明确数据范围、公式、单位、时间、去重、精度及实际需要的空值规则。
- [ ] 状态、权限、锁定、改派、关联、历史和初始化等本期规则没有因压缩而丢失。
- [ ] 重要失败写清结果与用户下一步；未确定的提交结果没有冒充失败并诱导重复执行。
- [ ] 多端差异、外部依赖和数据迁移等本期特殊能力得到说明。

## 阅读与篇幅

- [ ] 同一规则只有一个完整定义位置，引用可以定位，例外明确；字段不在多个字典中反复定义。
- [ ] 没有无适用内容的表格、空标题或“无独立搜索／不适用”凑项。
- [ ] 简单弹窗随操作说明，共用表单合并；只有复杂独立任务另设小节。
- [ ] 图表确实帮助理解，未给每页强配 ASCII、保存流程和逐节点解释；复杂流转仍有必要表达。
- [ ] 未默认输出覆盖矩阵、节点对账、模板映射、逐页证据、完整技术契约或完整测试用例，也未把它们整体搬到附录。
- [ ] 没有“以下略／后续同样输出”替代业务内容；验收要点没有再复制整份规则。

## AI 与交付

- [ ] 仅当本期确有 AI 能力时补充 AI 说明；产品名字含 AI 不触发整套模板。
- [ ] AI 输入、输出、人工控制、重要失败和效果验收可判断；未凭空增加 Agent、提示词或数据集。
- [ ] 原型/资料链接可定位，本地图片路径相对交付文档有效；Markdown 表格和围栏闭合，使用的 Mermaid 可解析。
- [ ] 真实待确认问题有具体影响；阻断核心交付时标草稿，不声称全部就绪。

## 技能维护时的场景回看

修改本技能后，用以下场景核对入口、模板和检查清单的决策是否一致。它们是行为评审案例，不要求额外调用模型或生成测试文件。

- 只有编号/名称的新建与编辑弹窗：应共用字段说明、列差异，不生成筛选表、逐弹窗图和完整工程契约。
- 跨角色审批且存在回退：仍应说明条件、角色、状态与回退影响，不能为了短而删掉关键分支。
- 在保金额统计：仍要明确数据范围、求和/去重、单位及权限，不能只写“展示金额”。
- 只有金额区间变化的迭代：写本期边界、端差异及沿用的旧流程，不复制全系统 PRD。
- 产品名称为“AI 平台”的排期管理：没有模型任务时按常规需求写，不造 Agent。
- 含 OCR 回填且允许人工修正：补输入、回填/覆盖、失败和人工确认，不默认附提示词与训练集。
