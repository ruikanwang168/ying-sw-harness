# 输出模板索引

> 三层体系见 [references/requirements-layers.md](../references/requirements-layers.md)。按用户要求选用一层或多层，**自上而下**生成。

## 1. 用户故事

模板：[user-story-template.md](user-story-template.md)

生成前先内部完成：

- 核心诉求：一句话业务结果，不含页面名、按钮名、系统名、工具名。
- 手段清单：页面、字段、按钮、跳转、iframe、集成方案；仅用于功能需求、常规研发需求和产品研发需求清单。

## 用户故事

作为【用户角色】，  
在【业务场景 / 触发条件】下，  
我希望【完成某项任务 / 达成某个目标】，  
以便【获得业务价值 / 解决用户问题】。

## 验收标准

（AC1–AC3 起，用户应能够…）

## 2. 功能需求

模板：[functional-requirements-template.md](functional-requirements-template.md)

## 功能需求：【功能名称】

系统应提供【功能名称】能力，  
支持【用户角色】在【业务场景】下完成【核心业务任务】，  
并围绕【业务对象】进行【核心操作集合】，  
以满足【业务目标】。

### 功能范围 / 关键信息 / 业务规则 / 验收标准 AC1–AC5

（见功能需求模板全文）

关联功能需求：【…】

### 需求描述

（简要说明系统能力、覆盖范围、预期结果；关键处理按「当【用户角色】在【页面/模块/场景】…系统应根据…完成…并返回/展示/保存/更新…」；勿输出公式 blockquote）

（见研发需求模板全文；AC 用「在【前置条件】下，当…系统应产生【可验证结果】，并满足【数据、状态、权限、异常、反馈】…」）

## 输出层级选择（未指定时）

以 [requirements-layers.md](../references/requirements-layers.md#默认输出策略) 为唯一权威来源。

- **兜底**：用户故事 + 功能需求  
- **集成/落地类输入**：+ 常规研发需求  
- **页面/清单类输入**：+ 产品研发需求清单  
- **页面 + 集成均明确**：清单 + 常规研发需求分别输出  
- **纯业务痛点**：可仅用户故事  

## 全套输出顺序建议

1. `## 用户故事` + 验收标准  
2. 一个或多个 `## 功能需求：…`  
3.（若含研发落地）常规研发需求 和/或 产品研发需求清单
4. 输出前检查用户故事：不得出现「系统应」、页面/按钮/字段/跳转/iframe/工具名；条数按独立业务目标判断，不按页面控件拆分
