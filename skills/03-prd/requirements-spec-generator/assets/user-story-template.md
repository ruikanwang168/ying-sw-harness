# 用户故事推荐模板

> **原则**：用户故事写的是**用户想要什么价值**（谁在什么场景下，为什么需要）；验收标准写的是**怎样判断这个价值真的被满足**。  
> 验收标准主语用「用户应能够」，不写「系统应提供/展示/跳转」。  
> 产品功能见 [functional-requirements-template.md](functional-requirements-template.md)；实现规格见 [rd-requirements-template.md](rd-requirements-template.md)。

---

## 用户故事

作为【用户角色】，  
在【业务场景 / 触发条件】下，  
我希望【完成某项任务 / 达成某个目标】，  
以便【获得业务价值 / 解决用户问题】。

---

## 验收标准

### AC1：【结果名称】

在【前置条件】下，  
当【用户执行关键动作】时，  
用户应能够【获得明确结果】，  
并且【结果达到的质量标准 / 业务约束】。

### AC2：【异常或边界场景】

在【异常条件 / 边界场景】下，  
当【用户继续执行任务】时，  
用户应能够【获得提示 / 修正路径 / 替代方案】，  
并且【不会影响核心任务完成 / 不会造成错误结果】。

### AC3：【任务完成标准】

当【用户完成核心任务】后，  
用户应能够【将结果用于后续业务流程】，  
并且【相关人员可以基于该结果达成一致 / 继续推进】。

---

## 补充说明

- 默认至少包含 **AC1（主路径）+ AC2（异常/边界）+ AC3（完成与后续使用）**；主路径有多个独立结果时可增加 AC1.x，仍保持上述四行结构。
- 「我希望」应写**业务目标与价值**，不写产品功能、菜单、集成方案（手段写入研发需求）。
- 生成前仍须完成**核心诉求识别**与**手段清单**（见 SKILL.md）；输出时以本模板为准，手段不进入「我希望」句。
